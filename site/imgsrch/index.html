Search screenshots by what they say and what they mean.

Small vision models read each image once, on your machine. Natural language finds it again. Your images never leave your machine. For humans and agents.

~/Screenshots
$ ./imgsrch search shots "that post about engineering ownership"
1 images/IMG_7741.PNG Screenshot of a post about engineering ownership: “strong teams own outcomes, not tickets” …
2 images/Screenshot 2026-03-14 at 9.12.03.png Slide titled “Ownership vs. accountability” with a two-column comparison …

Index in the background. Search anytime, offline.

why

The useful screenshots were already there

My iPhone screenshots kept accumulating, but giving hundreds of images to an agent was impractical and wasteful. imgsrch processes them locally once and retrieves a small relevant set, so a person or agent opens only the evidence needed for the task.

workflow

The whole tool

$ ./imgsrch init shots
$ ./imgsrch index shots ~/Screenshots/*.png
queued: 24 image(s) · skipped: 46 already indexed · work continues in the background
$ ./imgsrch search shots "diagram explaining KV cache"
  • setupDownload the three pinned models: 3.4 GB, checksum-verified, once
  • initCreate a project
  • indexIndex as you go: new images queue, already-indexed are skipped
  • statusRead-only progress: what finished, what failed and why
  • searchNatural language in, ranked files with matched text out

Plus add and doctor. That’s the daily surface.

mechanics

How search works

image ─► caption + OCR ─► index
query ─► dense + BM25 ─► RRF

RRF is the default because it measured better on a labeled hard set. imgsrch eval keeps the claim checkable.

no black box

The index is plain files

shots/.imgsrch/
├── artifacts/<image>/
│   ├── caption.txt
│   ├── ocr.txt
│   ├── combined.md
│   └── embedding.json
├── index/index.tsv
└── workspaces/

No database. If a search result surprises you, the reason is a file you can open.

for agents

Agents can use it

Agents search first, read matched captions and text, and open originals only for verification.

One command, stable text output: ranked files with cited paths. A small candidate set, not an image library.

install

One archive, no dependencies

$ tar -xzf imgsrch-darwin-arm64.tar.gz
$ cd imgsrch-darwin-arm64
$ ./imgsrch setup   # fetches the pinned models, once
  • imgsrch-darwin-arm64.tar.gzmacOS 13.3+, Apple Silicon
  • imgsrch-darwin-x86_64.tar.gzmacOS 13.3+, Intel
  • imgsrch-linux-x86_64.tar.gzLinux x86-64, AVX2

Everything is bundled except the models. CPU-first, no GPU required. SHA-256 checksums ship next to each archive. macOS builds are unsigned; the first run may need approval in System Settings → Privacy & Security.

imgsrch is pre-beta. It does one thing: search your screenshots. It's early. If something breaks, open an issue; every report gets read.
